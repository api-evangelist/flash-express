# Flash Express

> Flash Express is a Bangkok-headquartered express parcel delivery and e-commerce logistics operator serving Thailand, with affiliated operations in the Philippines and Laos. It publishes the FlashExpress Open API, a merchant-facing integration surface for creating shipments, printing labels, tracking parcels, scheduling courier pickups and subscribing to delivery webhooks.

Generated by API Evangelist from the provider's public developer documentation. Flash Express does not
publish an llms.txt of its own — https://open-docs.flashexpress.com/llms.txt and
https://flashexpress.com/llms.txt were both probed and neither serves a real document (the docs host
returns its SPA catch-all HTML index for every unmatched path; the corporate host returns an empty
zero-byte 200).

## What an agent needs to know first

- There is **no OpenAPI, AsyncAPI, GraphQL or MCP surface**. The reference is human-readable HTML only.
- **Every operation is HTTP POST**, including reads. HTTP method carries no semantics.
- Requests are **application/x-www-form-urlencoded**; responses are JSON.
- **Business errors return HTTP 200.** Branch on the `code` field in the body, never on HTTP status.
  `code: 1` is success, `code: 0` is a server error, `1000+` are specific business errors.
- Authentication is **SHA256 shared-secret request signing** (`mchId` + `nonceStr` + `sign`), not a
  bearer token and not OAuth. The secret key is issued only by Flash Express support.
- **Weight is always grams** and **money is always integer cents** (1 THB = 100 cent). Convert before
  calling; there are no unit fields and no currency code.
- **There is no idempotency key.** A duplicate create fails with code 1003 rather than replaying.
- **No rate limits are published** and no rate-limit headers exist. Pace conservatively.

## APIs

- [FlashExpress Open API](https://open-docs.flashexpress.com/): Merchant integration API for orders,
  labels, tracking, pickup scheduling and webhooks. Production base URL
  `https://open-api.flashexpress.com`; training base URL `https://open-api-tra.flashexpress.com`.

## Operations

Management
- `POST /open/v1/warehouses` — list the merchant's registered pickup warehouses
- `POST /gw/fda/open/standard/address_core/url/query` — retrieve the Flash standard location tree
- `POST /open/v1/new_sub_account` — create a sub-account

Orders
- `POST /open/v3/orders` — create an order
- `POST /open/v3/ordersByMchPno` — create an order against a merchant-supplied tracking number
- `POST /open/v1/orders/modify` — modify an order
- `POST /open/v1/orders/{pno}/cancel` — cancel an order
- `POST /open/v1/orders/{pno}/routes` — track one parcel
- `POST /open/v1/orders/routesBatch` — track parcels in batch
- `POST /open/v1/orders/{pno}/deliveredInfo` — retrieve proof of delivery
- `POST /open/v1/orders/{pno}/pre_print` — render a 100x180mm label
- `POST /open/v1/orders/{pno}/small/pre_print` — render a 100x75mm label
- `POST /open/v1/orders/estimate_rate` — estimate a freight rate

Pickup notifications
- `POST /open/v1/notifications` — list pickup schedules by date
- `POST /open/v1/notify` — schedule a courier pickup
- `POST /open/v1/notify/{id}/cancel` — cancel a pickup schedule

Webhooks
- `POST /open/v1/setting/web_hook_service` — configure or close a webhook callback URL
- `POST /gw/fda/open/standard/webhook/setting/infos` — read current webhook settings

## Events

Five webhook types, selected by `webhookApiCode`: status (0), weight (1), price (2), courier (3),
routes (4). Callbacks are signed over `mchId` and `nonceStr` only. The merchant endpoint must reply
with an HTTP status in [200,300) **and** a body of `{"errorCode":"1","state":"success"}`, or Flash
Express resends automatically until it does. There is no manual replay endpoint.
